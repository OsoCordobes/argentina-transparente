## Schema Inconsistencies & Type Mismatches

### CUIT/DNI Format Variations (Critical)
- **CUIT** stored as TEXT in: `contratos.proveedor_cuit`, `empresas.cuit`, `igj_entidades.cuit`, `personas_juridicas.cuit`, `boletin_actos.cuit`, `aportantes_campanas.cuit`
  - FORMAT INCONSISTENCY: Some seeds normalize to dashes (XX-XXXXXXXX-X), others strip to digits-only
  - **RISK**: Cross-table JOINs on CUIT fail silently if one side has dashes and the other doesn't
  - **MITIGATION**: `db.ts` line 1526 uses `REGEXP_REPLACE(CAST(cuit AS VARCHAR), '-', '', 'g')` to strip dashes before IGJ CSV INSERT; other seeds don't normalize consistently
  
- **DNI** stored as TEXT in: `agentes_publicos.cuit` (misnamed), `igj_autoridades.numero_documento`, `personas_fisicas.dni`, `cargos_funcionarios.dni`
  - FORMAT INCONSISTENCY: numero_documento may have dashes or alphanumeric, others expected INT-only
  - **RISK**: Identity resolution fails if fuzzy matching assumes numeric-only format

### Date/Timestamp Type Variations
- **TEXT**: `contratos.cargado_en`, `presupuesto_ejecucion.cargado_en`, `personas_fisicas.primer_visto` (TIMESTAMP in CREATE TABLE but populated as TEXT ISO strings)
- **TIMESTAMP**: `declaraciones_juradas.t_efectivo`, `personas_fisicas.ultimo_visto`, `pagos_contrato.t_publicado`
- **RISK**: Date range filters on TEXT fields fail without CAST(cargado_en AS TIMESTAMP); Bitemporal fields (t_efectivo/t_publicado) only in Phase W1 tables

### JSON Columns (Untyped)
- `personas_fisicas.fuentes_url_json` (array of URLs, TEXT)
- `personas_juridicas.alias_json` (array of alternative company names, TEXT)
- `cargos_funcionarios.facultades_json` (JSON array of role capabilities, TEXT)
- `boletin_actos.detalle` (quarantine error details, TEXT)
- **RISK**: No schema validation; if inserted data doesn't parse as valid JSON, downstream code breaks

### Monetary Amounts
- **DOUBLE**: `contratos.monto`, `presupuesto_ejecucion.credito_initial/vigente/compromiso`, `pagos_contrato.monto`
- **RISK**: DOUBLE has precision loss for ARS currency; accounting balances may be off by centavos at scale

## Critical Findings

### 1. **Tier 1-3 vs Tier 4-5 CUIT Split** (db.ts line 79)
   - `contratos.proveedor_cuit` = verified (identity resolver Tier 1-3)
   - `contratos.proveedor_cuit_inferido` = LLM-guessed (Tier 4-5, unreliable)
   - **RISK**: Detectors using `proveedor_cuit_inferido` will emit false positives (documented in schema comment)

### 2. **Identity Resolution Fragmentation** (lines 816-831)
   - `identity_matches` table caches resolution results by `proveedor_norm` (TEXT PK)
   - If normalization changes (e.g., how suffixes are stripped in `normProveedor()`), cache becomes stale
   - **No cache invalidation mechanism** → old mismatches persist

### 3. **Bitemporal Data Only in Phase W1 Tables** (lines 869, 914, 1013)
   - Only `declaraciones_juradas`, `aportantes_campanas`, `pagos_contrato`, `cargos_funcionarios`, `personas_juridicas` have (t_efectivo, t_publicado, snapshot_id, superseded_by_id)
   - **MISSING** from: contratos, presupuesto_ejecucion, agentes_publicos, transferencias
   - **RISK**: Can't distinguish "data corrected upstream" from "data never existed"

### 4. **Partial Index Coverage** (lines 89, 193-210, 317-320)
   - Some tables have comprehensive indexes (igj_autoridades: 3 indexes, declaraciones_juradas: 4 indexes)
   - Others have NONE: boletin_actos (5 defined in db.ts 410-414 but created at runtime), licitaciones_llamado (0 indexes)
   - **RISK**: /actores search by name will full-scan igj_autoridades (2.29M rows) without index DESPITE CREATE INDEX IF NOT EXISTS at line 208

### 5. **Name Normalization Inconsistency** (lines 1574-1580)
   ```ts
   .replace(/\s+(S\.?A\.?S?\.?|S\.?R\.?L\.?|S\.?C\.?S?\.?)\s*$/, '')
   ```
   - Strips "SA", "SRL", "SCS" suffixes to avoid false non-matches
   - **BUG**: Regex `.?A\.?` matches "SPA" (single char "A") → "SPA SA" becomes "SPA S" not "SPA"
   - Some seeds may populate with "EMPRESA SA" while queries search "EMPRESA" → JOIN misses

### 6. **NULL vs Empty String Defaults** (ALTER patterns throughout db.ts)
   - Most TEXT fields default to NULL or empty string inconsistently
   - Example: `apellido_nombre_norm TEXT DEFAULT ''` (line 887) vs `apellido_nombre_norm TEXT` (CREATE TABLE line 950)
   - **RISK**: `WHERE apellido_nombre_norm IS NOT NULL` silently ignores pre-migration rows with empty string

### 7. **No Foreign Key Constraints** (deliberate, doc line 1000-1002)
   - `pagos_contrato.contrato_hash` references `contratos.hash` but NOT enforced
   - `identidad_candidates` has no FK to source tables
   - **RATIONALE**: Allows incremental seeding (contratos loaded before pagos), but means orphaned rows possible

## Recommendations

1. **Consolidate CUIT normalization** into a single function; audit all seeds for `XX-XXXXXXXX-X` vs digit-only mismatch
2. **Add bitemporal columns** to contratos, presupuesto_ejecucion, agentes_publicos (Phase W2)
3. **Implement cache invalidation** for identity_matches when normProveedor() changes
4. **Backfill DNS into agentes_publicos** (Phase A4 incomplete); currently only ~2% coverage
5. **Publish zombie schema** to schema registry so future connectors know target table + expected columns
6. **Add FOREIGN KEY constraints** post-hoc using `ALTER TABLE` once migration strategy is clear
